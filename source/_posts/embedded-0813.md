### 一、从数字电路和进制入手

在 MCU 中，很多 Cpp 表达式最终会直接对应硬件中的电压变化、寄存器位翻转和总线传输。比如对于该表达式：

```
GPIOx->ODR |= (1u << 5);
```

这里的 1 表示数值，u = unsigned 表示无符号整数。假如用 32 位二进制表示 1 ，则是 `00000000 00000000 00000000 00000001`，于是 1u << 5 变为 `00000000 00000000 00000000 00100000`。此时 bit 5 = 1，其他 bit = 0。所以 1u << 5 实际就是制造一个位掩码 mask `0010 0000`，对应十进制为 32 ，十六进制为 0x20。所以数值上 1u <<5 和 32u、0x20u一致。

在 STM32 GPIO（外设寄存器）中经常能看到 `GPIOA/B/C/…/X` → `ODR`，这里的 ODR 是 Output Data Register，即 GPIO 输出数据寄存器。假设一个 GPIO 外设有 16 个引脚 `PA0~PA15`，那么 ODR 寄存器的不同 bit 通常分别对应：

```
ODR bit0  → PA0
ODR bit1  → PA1
ODR bit2  → PA2
...
ODR bit5  → PA5
...
ODR bit15 → PA15
```

如果 ODR bit 5 = 1，那么 PA5 的输出数据就是逻辑 1，前提是 PA5已经配置成了 GPIO 输出模式。所以这个表达式的意思是，找到 GPIOX 指向的 GPIO 外设，然后访问其中的 ODR 寄存器，将 bit 5 置 1，其他 GPIO 输出不变。同样的，要将 bit 5 清零，则使用 `reg &= ~(1u << 5)`。

> 复习：补码参与复数的位运算。
>
> 二进制补码常用语表示有符号整数，对于 n 位整数，补码可以把加法器统一用于正负数计算。以 8 位为例，-1 表示为$11111111_2$，-2 表示为$11111110_2$。直观来说，负数二进制补码就是对正数绝对值按位取反再加1，如−5 : 00000101 →11111010 → 11111011。

#### 1. 组合逻辑、时序逻辑和寄存器

假设一个 AND 门 $Y=A \land B$，那么只需要知道**现在**的 A 和 B，就能唯一确定现在的 Y 。也就是说我不需要知道之前时间的 A 和 B 。按照这个道理，加法器本质是**组合逻辑**的：只需要告诉硬件当前的 A 和 B ，就能根据逻辑门组合得到 Sum 和 Carry，所以加法器本质是 AND、OR、XOR、NOT的组合。CPU 中的 ALU 很大一部分就是这样的组合逻辑。

但是如果计算机只有组合逻辑，那么假如 CPU 计算了 int a = 3 + 5， 那么 8 之后就无处可放。这里的无处可放意思是， 如果输入一旦发生变化，之前的 8 就会被舍弃，这就是时序逻辑的存在意义。

假设一个硬件单元，它有输入 D 和输出 Q。现在我们希望：当我让它保存 1 后，即使 D 后来变了， Q 仍然能保留原来的 1，直到下一次允许更新。于是可以设计这样一个时序逻辑电路：

```
             ┌──────────┐
D ──────────→│ D      Q │────────→
             │          │
CLK ────────→│ >        │
             └──────────┘
```

那么当时刻 t1 时，D = 1，CLK 到来，于是 Q ← 1，只要没有满足下一次更新条件，Q 仍然不变。这里的 CLK 是时钟，只有当 CPU/外设明确说“现在写入”时，寄存器才更新。可以理解成在规定的时钟瞬间，把 D 的值复制到 Q ，然后保留 Q。这样一个存储单元就是触发器，因此**一个 D 触发器可以粗略认为能够保存 1 bit**。

这里需要引入数电知识来解释为什么电路能记忆这 1 bit。实际上这个记忆最终仍是一种稳定的电路状态。所谓的数字电路保存 Q=1，其实就是让晶体管和节点电压处于代表逻辑 1 的稳定状态。那么自然地，如果一个存储单元能够保存 1 bit ，那么并排放 32 个 就能保存 32 bit，这就是一个最基础的 32 位寄存器。

#### 2. CPU 寄存器与 GPIO 的寄存器

现在就可以理解 CPU 寄存器是 CPU 内部的硬件存储结构。比如 Cortex-M CPU 内部存在 R0、R1、R2、…、R12、SP、LR、PC、XPSR。这里的 R0 就是一个 32-bit CPU 寄存器。若 CPU 执行 `MOV R0, #5`，那么R0对应的硬件状态就变成了`00000000 00000000 00000000 00000101`。若执行 `ADD R2,R0,R1`，那么CPU会这样执行：

```
R0 ─┐
    ├→ ALU 加法器 → 结果 → R2
R1 ─┘
```

在这个执行过程中，R0 / R1 通过时序逻辑保存输入，ALU 通过组合逻辑进行运算， R2 通过时序逻辑保存结果。

以上讲的是CPU寄存器，但是在 STM32 中，GPIOA->ODR并不是 R0 这种寄存器。因为 STM32 不只是有 CPU，整个 STM32 芯片大概是如下组成的：

```
                 STM32 芯片

┌──────────────────────────────────────┐
│                                      │
│       Cortex-M CPU                   │
│       ┌──────────┐                   │
│       │ R0       │                   │
│       │ R1       │                   │
│       │ PC       │                   │
│       │ ALU      │                   │
│       └────┬─────┘                   │
│            │                         │
│         Bus 总线                      │
│            │                         │
│   ┌────────┼─────────┬──────────┐    │
│   ↓        ↓         ↓          ↓    │
│ SRAM     GPIO       UART       TIM   │
│          │           │          │    │
│         MODER        CR1        CNT  │
│         ODR          BRR        PSC  │
│         IDR          DR         ARR  │
│                                      │
└──────────────────────────────────────┘
```

所以这样看就知道，ODR 其实只是 GPIOA 外设内部的一个硬件寄存器，而非 Cortex-M CPU 内部的 R0 / R1。STM32 的 CPU 操作 ODR，使用的是最关键的思想 Memory-Mapped I/O（内存映射I/O)。

CPU 拥有一套统一的地址总线，所有地址都属于同一个地址空间：

- 访问 `0x2000xxxx`：读写内存 SRAM
- 访问 `0x4000xxxx`：访问硬件外设内部的寄存器。

CPU 和外部硬件通信称为 I/O ，那么 CPU 如何区分读写内存还是操控外设？历史上有两套方案：端口映射 I/O 和内存映射 I/O。对于 x86 电脑而言，一般采用独立 I/O 端口，此时具有两套完全独立的地址编号，一套是**内存地址空间**，专门给内存条使用；一套是 I/O 端口地址空间， 专门给外设硬件使用。此时 CPU 具有两套指令：

- `MOV`：只能访问内存地址；
- `IN / OUT`： 专门访问 I/O 端口，不能访问内存。

第一套方案的工作流程大致是：CPU 执行 `OUT` 指令→ CPU内部硬件切换信号通知总线→外设电路监听 I/O 端口总线，匹配地址后响应。

第二套方案只有一套全局地址编号，此时内存、外设寄存器全部进入同一个地址空间，此时地址空间人为划分为：

- `0x08000000 ~ ...` → Flash（程序闪存，断电数据保留、擦写很慢、主要用来存固件代码）

  `0x20000000 ~ ...` → SRAM（静态随机存储器，断电丢失、读写极快、程序运行时临时存放代码）

  `0x40000000 ~ ...` → 所有外设寄存器 (GPIO、USART、TIM、ADC)

> 值得注意的是，STM32 内部的 RAM 是SRAM，而台式机、笔记本内存条一般是 DRAM。
>
> 在 SRAM 中，一个 SRAM 存储单元由**6个晶体管**组成触发器， **没有电容**。通电状态下，电路稳定维持0o or 1，只要不断电，数据就会一直保持不会刷新。使用 SRAM 的缺点是每 bit 占用的晶体管多、面积大。
>
> 在 DRAM 中， 一个存储单元只由 1个晶体管和 1 个电容组成，原理是用电容里有无电荷来表示 0 和 1。但是电容会漏电，哪怕不读写，电荷也会漏光，所以硬件必须周期性执行刷新操作，补足电荷。

#### 3. 一次 ODR 更新发生的过程：MODER 和 OTYPER 的作用

假设现在需要让 CPU 执行：向地址 `0x40020014` 写入 `0x20`，那么这时会把信息 `address = 0x40020014`、`data    = 0x00000020`放到总线上，并附赠 write =1 ，总线会经过地址译码器（组合逻辑）判断当前地址属于哪个部分的。

所以对于一个变量可以分成两种情况：

1. 普通变量 `uint32_t x=5`：最终可能放在 SRAM 中
2. `GPIO->ODR = 0x20`：被总线送到 GPIO 外设，使 ODR 改变。

但如之前所说的，寄存器更新并未改变引脚电平，仅仅是修改了 ODR 的bit 而已，此时每一位 bit 连接到 GPIO 的内部输出控制逻辑电路：

- ODR 第 5 位 = 1 →经过某些操作后选择输出高电平通路
- ODR 第 5 位 = 0 → 经过某些操作后选择输出低电平通路

这里的通路，其实就是GPIO 引脚内部的晶体管开关。对于 PA5 ，它可以被芯片内部的不同电路（输入电路、输出电路、复用外设过程）。STM32 GPIO 有一个 MODER（Mode Register，模式寄存器），对于每一个 GPIO 引脚，通常用 2 bit 来选择模式：

- 00：输入模式 Input；01：输出模式 Output；

  10：复用功能模式 Alternate Function；模拟模式 Analog；

##### ① Input

假设 PA5 外面接了一个按钮：`3.3V——按钮——PA5`，此时我并不希望 STM32 给 PA5 输出电压，而是希望**外面的电压是多少，我需要读取回来**。

于是 PA5 的方向是： `外部世界→PA5→输入电路→IDR（Input Data Register）→CPU`，这就是输入模式。具体来说就是 GPIO 输入电路识别（PA5 外部 = 3.3V） 为逻辑1 → IDR bit 5 = 1。那么软件就可以这样来检测：

```c++
if (GPIO->IDR & (1u << 5)){
    // PA5 当前检测到高电平
}
```

##### ② Output

例如 PA5 外面接 LED：`PA5——电阻——LED——GND`，此时希望**STM32 主动决定 PA5 是高电平还是低电平**。那么方向就相反了：`CPU→ODR→输出控制逻辑→输出驱动晶体管→PA5→外部电路`，这就是输出模式。

回到之前的内容，那么ODR在“选择输出高/低电平”通路之前还需要插入一层：

```
              MODER
                │
                ↓
       PA5 是否属于 GPIO 输出？
                │
               Yes
                ↓
               ODR
                │
           输出 0 还是 1？
                ↓
              OTYPER
                │
          用什么输出电路实现？
                ↓
               PA5
```

现在假设 MODER = Output， 那么STM32如何真的把 0 / 1 变成 PA5 上的 0V / 3.3 V？这就是 OTYPER（Output Type Register）的作用，它**决定输出驱动电路长什么样子**。具体来说主要有两种：

- 0 → Push-Pull 推挽（推向高电平、拉向低电平，故称推挽）
- 1 → Open-Drain 开漏

GPIO内部可以极度简化这样的形式：

                 VDD = 3.3V
                     │
                 ┌───┴───┐
                 │ 上晶体管 │
                 │   Q1    │
                 └───┬───┘
                     │
                     ├──────── PA5
                     │
                 ┌───┴───┐
                 │ 下晶体管 │
                 │   Q2    │
                 └───┬───┘
                     │
                    GND

晶体管可以理解成电控开关，于是整个 GPIO 有两个开关：上开关 `VDD——Q1——PA5`负责把PA5接到3.3 V、下开关`PA5——Q2——GND`负责把 PA5 接到 0V。

对于推挽下 **ODR = 1** ，此时 MODER = Output，OTYPER = Push-Pull，ODR5 = 1，于是输出控制逻辑看到1，使得上管 Q1 导通、下管 Q2 = 关断 ，那么使得 PA5 $\approx$ 3.3 V，此时我们称 **PA5 输出逻辑高电平**；同理，对于推挽下 ODR = 0，那么 PA5 接到 GND，所以为 0V 低电平。

值得注意的是，这里**推挽模式下都是主动拉高/拉低**，也就是硬件真的主动把 PA5 连接到电源 VDD 或 GND 上。对比开漏模式，最根本的区别是开漏**没有主动拉高能力**，可以理解为去掉了上开关而只留下了一个开关，所以**开漏模式下 ODR = 0 可以主动拉低**。但是，如果开漏模式下，ODR = 1呢？这个时候下晶体管关闭、上面又没有通道，那么 PA5 是多少伏？答案是不知道，此时的 PA5 处于**高阻态 High Impedance**，也经常简称为 Hi-Z。

高阻态近似定义为 PA5 没有连接任何东西，就像是电路里的一个开关彻底断开，所以 PA5 可能受到外部电路、电磁干扰、漏电流、寄生电容的影响，因而 PA5 会发生 **floating 悬空**（乱飘）。

那么为了让开漏模式下让 PA5 获得高电平，必须在引脚PA5 和 VDD 之间加一条**上拉电阻**通路，一般有两种选择：

1. 外部上拉电阻：PCB 上焊电阻，引脚→电阻→ VDD
2. 开启芯片内部上拉电阻 PUPDR （单片机内置弱上拉电阻）

物理过程如下：ODR=1 → 内部管子全部断开 → 电流从 VDD经过上拉电阻流到 PA5 → PA5 被电阻抬升到接近 VDD， 呈现高电平。

那么为什么要区分开漏模式和推挽模式呢？

1. 推挽上 MOS 管： MOS 管导通内阻很小，驱动能力很强，可以输出较大电流（低阻抗）
2. 开漏上电阻上拉：相当于通过一个限流电阻接到电源上，上升沿（阻抗高）慢、下降沿（直接对地）快。

这样的开漏模式可以有一个巨大的优势：**多个设备可以安全的共用一根线，最经典的就是$I^2 C$**。假设两个设备共用 SDA：

```
                3.3V
                  │
                上拉
                  │
                  ├──────── SDA
                  │
          ┌───────┴────────┐
          │                │
       Device A         Device B
          │                │
       开漏管           开漏管
          │                │
         GND              GND
```

每个设备都只有两种行为：拉低 or 放手，不存在主动强推 3.3V 的行为，因此非常适合总线共享。至于复用模式和模拟模式，后续使用 UART 和 ADC 的时候会详细分析。
