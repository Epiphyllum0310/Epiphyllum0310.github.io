### 一、CPU 如何执行 C++ 代码

本章建立的是如何从 C++ 代码到机器指令再到 CPU 硬件动作，这是整个 MCU 的组成。本文以 STM32 常用的 **Cortex-M4 内核**为具体示例，它基于 ARMv7E-M 指令集架构，仅支持 Thumb-2 指令集（16 位 + 32 位混合编码），不支持传统 ARM 32 位指令集。

真实的 Cortex-M 可能具有更具体的 I-Code、D-Code、System bus等接口，不同内核是否具有 Cache、MPU 或 MMU也不同。目前这张图只是保留对 C++、STM32 和计算机组成原理最有价值的层次：

![CPU体系结构总览](/images/embedded/20260814/CPU体系结构总览.png)

对于这张图，可以先抓住两条主线：

- 指令线：PC 指向某条机器指令，处理器取回、译码，然后让执行单元完成动作；
- 数据线：数据在寄存器中参与计算，需要访问内存或外设的时候，再通过 Load / Store 和系统互连发起访问。

后续的内容都只是把这两条主线放大。

#### 1. 体系结构寄存器：R0-R12、SP、LR、PC 与 xPSR

CPU 真正执行指令的时候，最靠近执行单元的数据通常先放在**寄存器**中。以 Cortex-M4 为例，可以把最常见的寄存器分成两类：通用寄存器（R0-R12）、特殊用途寄存器（SP、LR、PC、xPSR）。这两者的核心区别是：**R0-R12 主要用来存数据和做计算，而 SP、LR、PC、xPSR 等寄存器承担 CPU 运行机制中的固定职责**。

| 寄存器 | 简单理解                                        | 适用场合                       |
| ------ | ----------------------------------------------- | ------------------------------ |
| R0-R12 | 通用寄存器，保存整数、地址、中间结果等          | 表达式求值、参数传递、临时变量 |
| SP     | Stack Pointer，指向**当前栈的位置**             | 局部对象、函数调用、中断现场   |
| LR     | Link Register， 保存**函数返回**的相关信息      | BL 调用、函数返回、异常返回    |
| PC     | Program Counter， 保存当前 / 下一条**指令地址** | 取指、跳转、分支、调试         |
| xPSR   | CPU **当前状态**，包含条件标志等                | 比较、条件分支、异常状态       |

如果严谨一点，当然可以继续多分一个系统控制相关特殊寄存器，包含 PRIMASK、BASEPRI、FAULTMASK、CONTROL 等，SP 也可以展开为 MSP (Main Stack Pointer) 和 PSP (Process Stack Pointer)，xPSR 也可以从概念上展开为 APSR（算术状态）、IPSR（当前异常号）、EPSR（执行状态）。

值得注意的是，**PC 保存的是指令地址而非指令本身**，教材中经常多增加一个指令寄存器 IR 用来表达“刚取回、正在被译码的指令”。在实际的具体微架构中，这一状态可能由流水级寄存器等结构承担，所以 IR 常作为一个概念模型。

所以能很自然的理解，一个在源代码中的局部变量不一定会存储在 SRAM 中，因为优化器完全可能让其处于R0-R12 的某个寄存器中，甚至当这个局部变量未使用时，会被删除。

#### 2. 取指——译码——执行：机器指令如何流过 CPU

从 C++ 源代码转换到机器码再写入 Flash 大致是这样的流程：

```
C++ 源代码→编译器 Compiler → 汇编代码 Assembly → 汇编器 Assembler → 机器码 Machine Code→链接器 Linker → 最终可执行程序/固件→ 写入 Flash
```

在 MCU 中，程序固件通常存放在 Flash 中。**Firmware 本质上也是软件，只是通常与具体硬件紧密结合，并以程序映像的形式存储在设备的非易失性存储器中；它既可以运行在裸机环境，也可以运行在 RTOS 之上。**

由于 Flash 断电不掉数据，所以程序映像通常保存在 Flash 中。MCU 复位后，Cortex-M4 会从向量表读取**初始 MSP 和 Reset_Handler 地址**，并从 Reset_Handler 开始执行启动代码；启动代码完成 `.data` 搬运、`.bss` 清零等初始化后，再进入 `main()`。比如这个程序，其对应的存储地点就不同：

```c++
const char str[] = "hello";  // 存在Flash，属于固件一部分
int a = 1;                   // 存在SRAM
void main(void)
{
    // 函数代码本体存Flash
}

```

其中，PC 给出指令地址，而根据 PC 给出的地址，将机器指令从存储系统取进 CPU 的过程称为 **Fetch 取指**。取指的详细过程为：`CPU PC→（地址）→存储器接口→Flash→找到地址、返回此处的机器指令→CPU`。

之后从取指到译码的过程为`Flash→IR→Decoder`，正如之前所说的， 概念模型 IR 的大致作用是通过内部流水结构保存已经取回、等待译码的指令。这里的 Decoder 全称为 **Instruction Decoder 指令译码器**。

机器指令有固定的编码规范，ARM、RISC-V、x86 都预先规定好了指令格式。为了方便理解指令编码的核心思想，我们以**经典 ARM 32 位指令集（A32，Cortex-M 不支持）**的 `ADD Rd, Rn, Rm` 为例，说明 32 位机器码如何按字段拆分功能。另外，下面的 **I 位与 Operand2 仍然属于 ARM 32 编码**示例，用于理解“同一指令如何编码寄存器操作数和立即数操作数”，并不是 Cortex-M4 Thumb-2 的统一编码格式。

| Bit 位置 | 31:28  | 27:26      | 25            | 24:21  | 20         | 19:16        | 15:12      | 11:0                       |
| -------- | ------ | ---------- | ------------- | ------ | ---------- | ------------ | ---------- | -------------------------- |
| 字段名   | Cond   | 固定值00   | I             | Opcode | S          | Rn           | Rd         | Operand2                   |
| 含义     | 条件码 | 指令类标识 | 立即数/寄存器 | 操作码 | 更新状态位 | 第一源寄存器 | 目标寄存器 | 第二操作数（含 Rm 和移位） |

以 `ADD R0, R1, R2`为例，此时不更新状态标志

1. **Cond (31:28) = 1110。**含义为 AL（Always），无条件执行；
2. **27:26=00。**固定值，标识这是一条【数据处理类】指令；
3. **I 位 (bit 25) = 0。**0 表示第二操作数是**寄存器**，1 表示第二操作数是**立即数**。
4. **Opcode (24:21) = 0100。**0100 对应 **ADD 加法操作**；
5. **S 位 (bit 20) = 0。**当运算后**不更新 CPSR 标志寄存器**时为 0 ，否则为 1。
6. **Rn (19:16) = 0001。** 第一源寄存器编号 = R1
7. **Rd (15:12) = 0000。** 目标寄存器编号 = R0
8. **Operand2 (11:0) = 0000 0000 0010。**低 4 位 = Rm = 0010 ，为第二源寄存器 R2；高位全 0 代表不对 Rm 做移位。

> 注意：Cortex-M 使用的 Thumb-2 指令集编码格式与此不同，没有全局 4 位条件码字段，指令长度分为 16 位和 32 位两种。但「操作码 + 寄存器编号 + 操作数」的拆分思想是通用的。

##### ① APSR（xPSR 应用状态字段）

我们常说的运算标志位，位于 Cortex-M 的 **xPSR（程序状态寄存器）** 的 APSR（应用程序状态寄存器）字段中。它相当于 CPU 的运算状态仪表盘，实时记录上一次运算的结果状态，所有条件判断逻辑都要读取它的值来决定是否执行分支。

> 补充说明：传统 ARMv7-A/R 架构中对应的寄存器叫 CPSR（当前程序状态寄存器），还包含处理器模式、中断开关等字段。Cortex-M 系列已废弃 CPSR 命名，将状态拆分为 APSR、IPSR、EPSR 三部分，中断屏蔽等功能转移到 PRIMASK 等专用寄存器。

APSR 最高四位（bit 31 ~ bit 28）是核心条件标志位：

- **bit 31：N 标志（Negative，负标志）**：运算结果为负数时置 1，否则置 0。

- **bit 30：Z 标志（Zero，零标志）**：只有执行了会更新状态位的指令时，Z 位才会被硬件修改。若本次运算结果为 0，则 Z 置 1，否则置 0。

  这里需要区分两类指令：

  - 不修改标志位：对许多数据处理操作，可以通过是否采用更新标志的指令形式来控制 APSR 是否改变，例如常见的 `ADD/ADDS`、`SUB/SUBS`。不过 Thumb 指令存在多种 16/32 位编码，**具体是否更新标志还取决于所采用的编码形式及 IT 状态，因此不能只凭助记符做绝对判断。**
  - 修改标志位：带 S 后缀的数据处理指令（`ADDS`、`SUBS` 等），以及专门的比较 / 测试指令（`CMP`、`TST` 等，本质是只改标志、不存结果的运算）。

- **bit 29：C 标志（Carry，进位标志）**：无符号运算发生进位（加法）或借位（减法）时更新，加法进位置 1，减法借位置 0。

- **bit 28：V 标志（Overflow，溢出标志）**：有符号运算结果超出表示范围时置 1，例如两个正数相加得到负数。

对应到指令的条件执行逻辑：经典 ARM 指令集的 Cond 字段，本质就是和这 4 个标志位一一比对的模板。例如 Cond = 0000 对应 EQ 规则：读取 Z 位，若 Z=1 则指令执行，否则跳过。

> 需要注意：这种「每条指令自带条件码、任意指令都能条件执行」的特性，是经典 ARM 指令集的设计。Cortex-M 的 Thumb-2 指令集**仅分支跳转指令B\<cond\>**自带条件编码；**普通数据处理指令的条件执行，需要配合专门的 IT（If-Then）前缀指令实现**。
>
> ```asm
> IT EQ             ; IT指令：如果EQ条件成立，后续1条指令执行
> ADDEQ R0, R1, R2  ; 加法指令本身无条件码，跟随前面IT的条件
> ```

##### ② I 位：寄存器与立即数

ALU 做运算时，两个输入就叫操作数，于是送入第一个和第二个输入端口的分别称为第一操作数和第二操作数。对于 ARM 32 位数据处理指令的固定规则， 第一操作数 = Rn 寄存器的值，第二操作数 = Operand2 字段解析出来的值。

- I = 0：寄存器模式，此时 Operand2 字段拆为三部分，用来描述 【一个寄存器 + 可选的移位操作】。

  | Bit 位 | 11:7   | 6:5      | 4      | 3:0                 |
  | ------ | ------ | -------- | ------ | ------------------- |
  | 含义   | 移位量 | 移位类型 | 固定 0 | Rm 第二源寄存器编号 |

  此时 Decoder 从 Operand2 低 5 位取出 Rm 编号，发信号给通用寄存器堆，读出 Rm 的值；然后从 Operand2 高位取出移位参数，发信号给桶形移位器，对 Rm 的值做移位。最后将移位后的结果送入 ALU 的第二个输入端口，和 Rn 提供的第一操作数一起参与运算。

-  I = 1：立即数模式，此时第二操作数是常量，会把 bit 11:0 的 Operand2 字段拆成两个部分：

  | Bit 位 | 11:8          | 7:0            |
  | ------ | ------------- | -------------- |
  | 含义   | 旋转量 Rotate | 8 位立即数常量 |

  此时硬件会把 8 位立即数循环右移 Rotate * 2 位，扩展成 32 位的立即数，直接送进 ALU。对应的会变形时是

  ```asm
  ADD R0, R1, #5   ; 第二操作数是数字5，I位=1
  ```

整个加法对应的结构其实如下图所示。所以 CPU 执行 ADD 这一条算术指令本身时，其算术操作数来自寄存器或立即数，而不是由 ADD 直接读取 SRAM，也就是·采用 Register File → ALU → R0 的结构。因为 Register File 和 ALU 都在 CPU 内核的核心位置，访问延迟是 1 个时钟周期，和 ALU 运行速度完全匹配，也就是说可以在一个周期内完成这一个读写结构。而 SRAM 哪怕是芯片内置的，也在 CPU 内核之外，数据要经过总线、地址译码、数据通路才能到达，逻辑延迟过高。

```
           Register File
             寄存器组
        ┌────────┴────────┐
        │                 │
        ▼                 ▼
      R1 = 5            R2 = 7
        │                 │
        └────────┬────────┘
                 ▼
            ┌────────┐
            │  ALU   │
            │   +    │
            └────┬───┘
                 │
                12
                 │
                 ▼
              R0 = 12
```

#### 3. 执行完一次指令后的 PC 更新

在 ARM 体系结构寄存器编号中，R15 对应 PC。对于 Cortex-M4 使用的 Thumb-2 指令流，指令可能为 16 位或 32 位，因此顺序执行时，下一条指令地址可能相对当前地址增加 2 字节或 4 字节。

**另一方面，当 Thumb 指令读取 PC 作为操作数时，体系结构规定其值通常为当前指令地址 +4。这里的“+4”描述的是 PC 的体系结构读取语义，并不意味着每执行一条 Thumb 指令，下一条地址都固定 +4。**

但是对于条件执行指令的情况，就需要分析条件指令对于 PC 的作用。对于如 ADD、SUB 等普通数据处理指令，只会改通用寄存器而不会碰 PC；但跳转指令（B、BL、BX等）的核心功能就是主动修改 PC 的值，让 CPU 调到另一个地址取指。跳转分两种情况：

- 无条件跳转：比如 B label，直接把 label 的地址塞进 PC，此时一定跳转。
- 条件跳转：比如 BNE label、BEQ label。Cortex-M 的分支指令自带条件编码，执行时先读取 APSR 的标志位，条件满足就修改 PC 跳转，不满足就顺序执行下一条。

对于一个简单的条件判断案例

```c++
if (x == 0) {
    foo();
}
```

对应的汇编语言为：

```asm
CMP R0, #0      ; 比较 R0 和 0，本质是做减法，只改 APSR 标志位
BNE skip        ; 不相等（Z=0）就跳转到 skip，相等就顺序执行
BL foo          ; 调用 foo 函数
skip:
...             ; 后续代码
```

详细分析其中发生的事情：

1. 执行 `CMP R0, #0`：

   这是一条会更新标志位的指令，内部计算 R0 - 0。如果 R0 = 0，结果为 0 ，于是 APSR 的 Z 位 = 1；否则为 0 。执行结束后，控制流顺序进入下一条 `BNE skip`。

2. 执行 `BNE skip`：

   译码器从 **Thumb 条件分支 `B<cond>` 自身的编码字段**中识别条件，`NE` 对应条件编码 `0001`，含义是 Z = 0 时跳转。

对于循环分支，本质是对分支跳转的一种巧用，例如对于例子 `while (x < 10) {x++;}`，对应的汇编逻辑为

```asm
loop_start:
    CMP R0, #10     ; 比较 x 和 10，更新 APSR 标志
    BGE loop_end    ; 大于等于（不满足循环条件）就跳出循环
    ADD R0, R0, #1  ; x++
    B loop_start    ; 无条件跳回循环开头
loop_end:
    ...
```

所以所有控制流本质就是修改 PC：

- **顺序执行**：按照当前 Thumb 指令的实际长度，继续执行内存中的下一条指令。
- **if /switch 分支**：条件跳转指令，按 CPSR 标志决定 PC 改不改、改成多少
- **while /for 循环**：条件跳转 + 往回跳，让 PC 重复指向同一段代码
- **函数调用（BL）**：
  - 先把当前 PC 的下一条地址（返回地址）存到 LR 寄存器（R14）
  - 再把函数入口地址写入 PC，实现跳转
- **函数返回（BX LR）**：把 LR 里存的返回地址写回 PC，回到调用处继续执行
- **中断**：
  - 硬件自动把当前 PC、xPSR 等压入栈保存
  - 从中断向量表里取出中断服务函数的地址，写入 PC
  - 中断结束后，从栈里恢复原来的 PC 值，回到被打断的地方继续跑

以上全部过程其实都是再重复一件事：

```
              ┌─────────────────────┐
              │                     │
              ▼                     │
PC → Fetch → Decode → Execute → 更新状态
                              │
                              └──→ 下一PC
                                      │
                                      └─────────┘
```

> 如果局部变量在 SRAM 中，并且需要将计算结果存回 SRAM 中，就需要用 **Load / Store 架构**。这个步骤分为三步：
>
> 1. Load：用专门的加载指令，把 SRAM 中的数据搬回 CPU 内部寄存器。
> 2. 运算：使用数据处理指令 ADD / SUB 等，只在寄存器之间完成运算。
> 3. Store：用专门的存储指令，把寄存器的结果写回 SRAM。
>
> ```asm
> ; 假设：变量a在SRAM地址0x20000000，变量b在0x20000004，结果存0x20000008
> 
> ; 第1步：Load，把内存数据搬进寄存器
> LDR R1, =0x20000000   ; 载入a的地址
> LDR R1, [R1]          ; SRAM → R1  （加载第一个操作数）
> LDR R2, =0x20000004   ; 载入b的地址
> LDR R2, [R2]          ; SRAM → R2  （加载第二个操作数）
> 
> ; 第2步：运算，ALU只操作寄存器
> ADD R0, R1, R2        ; R1 + R2 → R0  （寄存器→ALU→寄存器）
> 
> ; 第3步：Store，把结果写回内存
> LDR R3, =0x20000008   ; 载入结果地址
> STR R0, [R3]          ; R0 → SRAM  （存储结果）
> ```
>
> 对应的数据流图为
>
> ```
> SRAM / 地址空间
>       │ ↑
>       │ │
>       ▼ │
> 总线 / 存储器接口
>       │ ↑
>       ▼ │
> Load / Store Unit
>       │ ↑
>       ▼ │
> Register File
>       │ ↑
>       │ │
>       ▼ │
> ALU / Execution Units
> ```
>
> 值得注意的是，相比 ARM 这种典型 Load / Store 架构，x86 等 CISC 指令集允许某些算术指令直接使用内存操作数，因此 **x86 在 ISA 层面并不是纯粹的 Load / Store 架构**。现代 x86 处理器内部可能进一步把复杂指令拆分成多个微操作，但这是微架构层面的实现方式，不能据此认为 x86 ISA 本身也是 Load / Store。
